A popover is a transient UI component that displays contextual content in
a layer above the interface, typically triggered by user interaction like
clicking or hovering.

<br />
<ImageModal
  src={popover}
  alt="Popover"
/>

<br />A **Popover** is a contextual UI component that delivers supporting
information or lightweight actions anchored to a trigger element. It is
primarily used to clarify product details, highlight specifications, or surface
quick options relevant to e-commerce interactions. Designed for focus and
efficiency, it helps users access contextual guidance without interrupting their
main shopping flow in HP Store.

## Anatomy

The anatomy of the “Modal” component includes the following essential elements:

<br />

<ol class="custom-list">
  <li class="list-image-[url(/list/list1.svg)]">
    <h4>Container</h4>
    <p>
      The main surface that groups all internal elements of the popover. It
      defines the component’s boundary, provides elevation, and visually
      separates the popover from the underlying content.
    </p>
  </li>
  <li class="list-image-[url(/list/list2.svg)]">
    <h4>Header (optional)</h4>
    <p>
      A dedicated subcomponent instance placed at the top of the Popover. It may
      include a title, subtitle, leading icon, and/or close button. Its
      inclusion depends on the use case.
    </p>
  </li>
  <li class="list-image-[url(/list/list3.svg)]">
    <h4>Content area</h4>
    <p>
      The central and flexible zone of the popover. It displays the main
      information, controls, or interactive elements relevant to the user’s
      task. This is the functional core of the component.
    </p>
  </li>
  <li class="list-image-[url(/list/list4.svg)]">
    <h4>Footer actions (optional)</h4>
    <p>
      The bottom section of the popover reserved for complementary actions, such
      as links, confirmation buttons, or secondary interactions. Its inclusion
      depends on the specific use case.
    </p>
  </li>
  <li class="list-image-[url(/list/list5.svg)]">
    <h4>Arrow (optional)</h4>
    <p>
      A triangular visual indicator connecting the popover to its trigger
      element. It reinforces the spatial and contextual relationship between the
      content shown and the interaction point.
    </p>
  </li>
</ol>

## Properties

### Arrow indicator

The Arrow property controls the display of the arrow indicator in the Popover. This arrow visually connects the Popover to its trigger, pointing towards the element that activated it.

<ul>
  <li>
    <span class="font-bold">When enabled:</span> the arrow is rendered on the
    edge of the Popover, reinforcing the spatial relationship between the
    Popover and its trigger.
  </li>
  <li>
    <span class="font-bold">When disabled:</span> the Popover is displayed
    without the arrow, resulting in a cleaner and more neutral layout.
  </li>
</ul>

This property is boolean, allowing flexibility depending on whether the Popover needs to explicitly indicate its origin or remain minimal.

The Header property is a boolean option that allows enabling or disabling the header section of the Popover.

<ul>

    The Popover displays a title and an optional subtitle above the content
    area.
  </li>
  <li>

    The content is presented without a header, offering a more minimal layout.
  </li>

### Leading icon on header

The Leading icon property controls the display of an icon positioned to the left side of the header content.

<ul>
  <li>
    <span class="font-bold">When enabled:</span>
    An icon is placed before the header title, reinforcing the purpose or
    context of the Popover (e.g., an information icon, warning icon, or status
    symbol).
  </li>
  <li>
    <span class="font-bold">When disabled:</span>
    The header is displayed without any leading icon, maintaining a cleaner and
    more minimal layout.
  </li>
</ul>

This property is useful when additional visual context is required to help users quickly recognize the type of information or action presented in the Popover.

## Interaction definition

### Behavior

The Popover is always initiated by a trigger element (e.g., a button, icon, or any interactive control). When the user clicks, taps, or activates the trigger, the popover is displayed, presenting contextual content without replacing or blocking the rest of the interface.

<div class="rounded-3xl bg-[#bdf4e9] dark:bg-[#273d39] p-8">
  <p class="font-bold">Key interaction rules:</p>
  <ul>
    <li>
      The popover is anchored to its trigger and appears only in response to
      that action.
    </li>
    <li>
      It does not block interaction with the background or the rest of the
      viewport.
    </li>
    <li>The popover is dismissed when:</li>
    <li>The user clicks outside of it.</li>
    <li>The user presses the trigger element again.</li>
  </ul>
  <p>
    This behavior ensures that the popover remains a lightweight, contextual
    layer, providing information or actions without interrupting the user’s
    flow.
  </p>
</div>

### Auto-Placement

The Popover allows defining the preferred direction in which it will appear relative to its trigger element.
This is configured through the **placement property**, with the following common options: **top, bottom, left, right**

#### Behavior rules

<ul>
  <li>
    The developer defines the preferred placement through the component
    property.
  </li>
  <li>
    The system applies an auto-placement mechanism to ensure the Popover always
    remains visible within the viewport.
    <ul>
      <li>
        Example: if the placement is set to bottom but there is not enough space
        below, the Popover will automatically open on top.
      </li>
    </ul>
  </li>
  <li>
    The Popover always stays anchored to its trigger, adjusting dynamically to
    preserve alignment and readability.
  </li>
</ul>

#### Usage recommendations

<ul>
  <li>
    Use the default placement (bottom) unless the context explicitly requires
    another position.
  </li>
  <li>Avoid forcing placements that may conflict with other UI elements.</li>
  <li>
    Always consider responsiveness: on smaller screens, relying on
    auto-placement ensures a better experience.
  </li>
</ul>

## UX tips

<div class="rounded-3xl bg-[#bdf4e9] dark:bg-[#273d39] p-8">
  <ol>
    <li>
      <span class="font-bold">Clarity in Context:</span>
      Use popovers to provide users with brief, contextual information or quick
      actions related to a specific element. Ensure the content is directly
      relevant to the user’s current task.
    </li>
    <li>
      <span class="font-bold">Keep it Short and Focused:</span>
      Content in a popover should be concise and limited to essential
      information. Avoid long explanations, multiple steps, or unrelated
      content. If more detail is needed, use a modal or a dedicated page.
    </li>
    <li>
      <span class="font-bold">Trigger Appropriately:</span>
      Activate popovers using clear user actions typically click, tap, hover, or
      focus on an icon or element. Use click for more interactive content, and
      hover/focus for brief tips.
    </li>
    <li>
      <span class="font-bold">Easy to Dismiss:</span>
      Popovers should be easy to close by clicking outside, pressing the{" "}
      <span class="css-var">Esc</span> key, or blurring focus. Avoid persistent
      popovers that require extra steps to dismiss.
    </li>
    <li>
      <span class="font-bold">Do Not Block Workflow:</span>
      Popovers should never block user progress or require a decision to
      continue. For blocking interactions, use a modal instead.
    </li>
    <li>
      <span class="font-bold">Accessible Design:</span>
      Ensure popovers are accessible to all users, including those using screen
      readers. Use semantic HTML, manage focus, and provide clear relationships
      between the trigger and the popover content.
    </li>
    <li>
      <span class="font-bold">Visual Clarity and Placement:</span>
      Place popovers close to the triggering element and use an arrow or pointer
      to clearly indicate their source. Ensure popovers do not cover essential
      content or obstruct the workflow.
    </li>
    <li>
      <span class="font-bold">Responsive and Adaptable:</span>
      Popovers should adapt to different screen sizes and orientations. Make
      sure content remains readable and interactive on both desktop and mobile
      devices.
    </li>
  </ol>
  <p>
    By following these best practices, the ‘Popover’ component can be used
    effectively to provide helpful, contextual information and actions without
    interrupting or overwhelming the user.
  </p>
</div>
