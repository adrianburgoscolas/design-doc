A modal is an interactive window that appears on screen and blurs the background screen to focus the user’s attention on the modal’s action. For example, a modal can ask the user to confirm or cancel a choice.

<br />
<ImageModal
  src={modal}
  alt="Modal"
/>

<br />
The **Modal** component is a pop-up window that overlays the main content of a
user interface, dimming the rest of the screen to focus the user’s attention on
the information or actions presented within it. Modals are used for interactions
that require the user’s complete focus, such as confirmation forms, critical
alerts, or the collection of specific data. Typically, modals include a header,
a main content area, and a footer with action buttons, creating a self-contained
and focused environment that requires user interaction before returning to the
main application functionality.

## Anatomy

The anatomy of the “Modal” component includes the following essential elements:

<br />

<ol class="custom-list list-outside pl-7">
  <li class="list-image-[url(/list/list1.svg)]">
    <h4>Container</h4>
    <p>
      The outer structure that wraps and organizes all internal elements of the
      modal. It manages layout, spacing, and overall alignment.
    </p>
  </li>
  <li class="list-image-[url(/list/list2.svg)]">
    <h4>Header (optional)</h4>
    <p>
      The header is an optional section of the modal that provides context and
      helps communicate its purpose. It can contain the following elements:
    </p>
    <ul class="list-image-none list-disc">
      <li>
        Title: The main heading of the modal. It gives users a clear indication
        of the modal’s purpose or the task to be completed.
      </li>
      <li>
        Subtitle (optional): A secondary line of text placed below the title. It
        provides additional context or clarification when needed, but can be
        omitted if the title alone is sufficient.
      </li>
    </ul>
  </li>
  <li class="list-image-[url(/list/list3.svg)]">
    <h4>Close button (optional)</h4>
    <p>
      A dedicated action, placed at the top-right corner, that allows users to
      dismiss the modal quickly and accessibly.
    </p>
  </li>
  <li class="list-image-[url(/list/list4.svg)]">
    <h4>Content area</h4>
    <p>
      The central and flexible body of the modal. It displays the main
      information, interactive controls, or form elements required to complete
      the user’s task. This is the functional core of the component.
    </p>
  </li>
  <li class="list-image-[url(/list/list5.svg)]">
    <h4>Action group (optional)</h4>
    <p>
      The bottom section of the modal that groups one or more actions (e.g.,
      primary, secondary, or link actions). It provides clear decision points
      for the user and supports task completion.
    </p>
  </li>
  <li class="list-image-[url(/list/list6.svg)]">
    <h4>Footnote (optional)</h4>
    <p>
      The footnote is an optional text area placed at the bottom of the modal,
      below the footer actions. It is typically used for supporting information
      such as legal disclaimers, additional guidance, or contextual notes that
      complement the main content.
    </p>
  </li>
</ol>

## Properties

### Header

The header property is a boolean that defines whether the modal
header is displayed or hidden. The header is composed of a title and an optional
subtitle, and its purpose is to provide context for the content and guide the
user’s action.

<ImageModal
  src={header}
  alt="Definition of use of the 'Header' property"
  caption="Definition of use of the 'Header' property"
/>
<br />

### Subtitle

The subtitle property is a boolean that defines whether the modal subtitle is displayed or hidden. The subtitle appears directly below the title in the header area and is used to provide complementary context or clarification for the user’s action.

<ImageModal
  src={subtitle}
  alt="Definition of use of the 'Subtitle' property"
  caption="Definition of use of the 'Subtitle' property"
/>
<br />

### Close button

The close button property is a boolean that allows showing or hiding the modal’s close control, located in the upper-right corner of the header. This button provides users with a direct way to dismiss the modal in addition to the primary actions.

<ImageModal
  src={close_button}
  alt="Definition of use of the 'Close button' property"
  caption="Definition of use of the 'Close button' property"
/>
<br />

### Action group

The action group property is a boolean that allows showing or hiding the modal’s action group, located at the bottom of the container. This area usually contains the primary and secondary buttons that guide the user’s decision-making.

<ImageModal
  src={action_group}
  alt="Definition of use of the 'Action group' property"
  caption="Definition of use of the 'Action group' property"
/>
<br />

### Footnote

The footnote property is a boolean that allows showing or hiding an optional note at the bottom of the modal, placed below the action group. Its purpose is to provide complementary details, clarifications, or legal messages that are not part of the main content or actions.

## Use cases

### Desktop

In Orion, modals behave as overlay containers displayed centered on the viewport, blocking interaction with the background interface until the user completes an action or closes the modal. This pattern ensures that attention is fully focused on a critical task, such as confirming the removal of items from the cart or reviewing key transaction details. While the modal is active, underlying content remains inactive and visually dimmed to reinforce hierarchy and guide user decision-making within the HP Store flow.

<ImageModal
  src={desktop}
  alt="Use of the 'Modal' component on desktop devices"
  caption="Use of the 'Modal' component on desktop devices"
/>
<br />

### Mobile

On the smallest breakpoints, such as mobile devices, modals adapt to the bottom sheet pattern. Instead of appearing centered on the screen, the modal slides up from the bottom. This behavior is consistent with native mobile interaction patterns, improves reachability for thumb interaction, and preserves part of the screen context so that users don’t lose track of where they are in the flow. The bottom sheet design provides a more natural and efficient way to handle confirmations, selections, or quick tasks on mobile.

On tablets, modals adopt the small modal variation, which behaves like the desktop experience: the modal appears centered on the screen. This ensures consistency across medium and large breakpoints, offering a balanced use of available space while keeping the user’s focus on the task. In this way, Orion adapts modal behavior to the ergonomics of each device type, ensuring both usability and consistency across HP’s e-commerce ecosystem.

## UX tips

<div class="rounded-3xl bg-[#bdf4e9] dark:bg-[#273d39] p-8">
  <ol class="pl-5">
    <li>
      <span class="font-bold">Clarity in Purpose:</span> Use modals to capture
      the user’s attention for specific tasks such as form submissions,
      confirmations, or alerts. Ensure the modal’s header clearly communicates
      the purpose.
    </li>
    <li>
      <span class="font-bold">Concise and Relevant Content:</span> Keep the
      content within the modal focused and concise. Avoid overloading the user
      with too much information. The content area should only contain essential
      information or interactive elements needed for the user to complete the
      task.
    </li>
    <li>
      <span class="font-bold">Accessible and Intuitive Design:</span> Ensure the
      modal is accessible to all users, including those using screen readers.
      This involves using semantic HTML elements and ARIA roles appropriately.
      The design should be intuitive, with a clear distinction between different
      sections like the header, content area, and footer.
    </li>
    <li>
      <span class="font-bold">Close Options:</span> Provide a clear way for
      users to dismiss the modal, either through a close button in the header or
      an action button in the footer. Additionally, clicking outside the modal
      or pressing the ‘Esc’ key should close the modal.
    </li>
    <li>
      <span class="font-bold">Focus Management:</span> When a modal is opened,
      focus should automatically move to the first interactive element within
      the modal. Upon closing the modal, focus should return to the element that
      triggered the modal. This ensures a seamless and accessible user
      experience.
    </li>
    <li>
      <span class="font-bold">Responsive Design:</span> Modals should be
      responsive and look good on all screen sizes. Ensure that the modal adapts
      to different devices, providing a user-friendly experience on both desktop
      and mobile platforms.{" "}
    </li>
    <li>
      <span class="font-bold">Use of Action Blocks:</span> Utilize the action
      block in the footer effectively. Include primary actions (e.g., ‘Accept’,
      ‘Submit’) and secondary actions (e.g., ‘Cancel’) to provide clear options
      for users. Ensure buttons are appropriately labeled to reflect their
      functions.{" "}
    </li>
  </ol>
  <p>
    By following these best practices, the ‘Modal’ component can be effectively
    utilized to enhance user interaction and provide a smooth, accessible, and
    efficient user experience across different contexts within an interface.
  </p>
